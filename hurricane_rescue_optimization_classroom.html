0. 情境导入：飓风救援与快速估算

课程定位：这不是一堂“教学生怎么用 Python 调包”的课，而是一堂“教学生怎么像运筹学家一样思考”的课。目标是把一个模糊的现实问题拆成精确的数学结构。

唯一主线场景：飓风“海鸥”过境后，你负责把应急物资从仓库运到受灾城镇。你有 3 个仓库、3 个城镇、5 架直升机、72 小时窗口。

核心理念

优化 = 在“不得不接受”的限制下，做出最好的“交换”。

Takeaway：模型不会自己产生常识。如果你不写“B 镇不能被放弃”，它就会为了救更多人而把 B 镇放弃。 
# --- A 1-minute sanity check: can we even meet demand? ---
inventory = {'W1': 12, 'W2': 15, 'W3': 10}
demand    = {'A': 10, 'B': 12, 'C': 8}
heli_trips = 5 * (72 / 3)      # 5 helicopters, 3h round trip
heli_capacity = heli_trips * 2 # 2 tons per trip

print(f"Total inventory:   {sum(inventory.values())} tons")
print(f"Total demand:      {sum(demand.values())} tons")
print(f"Helicopter capacity: {heli_capacity} tons")
print("\nIf demand > inventory or demand > heli capacity,")
print("the model MUST allow shortage (slack) or it will crash.")

教师参考：原文解决方法

本模块的核心方法是“在限制下做最好的交换”。教学时应让学生先做一个 1 分钟 sanity check：比较总库存、总需求、总运力。如果需求大于运力，必须允许短缺（slack），否则模型会不可行。教师可强调：模型不会自动具备常识，所有伦理底线（如不放弃任何城镇）必须写成约束或惩罚。

1. 优化三要素：变量、约束、目标函数

任何优化模型都可以拆成三部分：

要素含义救援场景
决策变量你能决定的量xw,t,h = 第 t 小时从仓库 w 运往城镇 h 的吨数
约束条件不能突破的硬限制库存 ≤ 上限；直升机运力 ≤ 上限
目标函数衡量好坏的标尺最小化总损失 = 运输成本 + 缺货惩罚 + 延误惩罚

启发问题：A 镇说“我们需要 100 吨水”。这句话可以写成硬约束（送达量 = 100），也可以写成目标函数中的软惩罚（缺货就扣分）。选择取决于你是否能接受“救不够”的现实。

import pulp

# --- A toy LP: allocate water from 2 warehouses to 2 towns ---
prob = pulp.LpProblem("Toy_Rescue", pulp.LpMinimize)

# Decision variables: tons shipped
x = pulp.LpVariable.dicts("x", (['W1', 'W2'], ['A', 'B']), lowBound=0)

# Objective: minimize transport cost
prob += 3*x['W1']['A'] + 5*x['W1']['B'] + 6*x['W2']['A'] + 2*x['W2']['B']

# Constraints
prob += x['W1']['A'] + x['W1']['B'] <= 12, "W1_inventory"
prob += x['W2']['A'] + x['W2']['B'] <= 15, "W2_inventory"
prob += x['W1']['A'] + x['W2']['A'] == 10, "A_demand"
prob += x['W1']['B'] + x['W2']['B'] == 12, "B_demand"

prob.solve(pulp.PULP_CBC_CMD(msg=0))
for w in ['W1', 'W2']:
    for h in ['A', 'B']:
        print(f"{w} -> {h}: {pulp.value(x[w][h]):.2f} tons")
print(f"Minimum cost: ${pulp.value(prob.objective):.2f}")

核心引导提问

Q1（概念接入）：如果飓风刚过，你作为总指挥站在地图前，你脑子里的第一反应是哪三个问题？

参考方向 1：“我们有什么？”（库存、直升机、时间）→ 这是约束的物质基础。

参考方向 2：“我们要给谁？”（哪座城最急？）→ 这反映了目标函数中的权重分配。

参考方向 3：“我们能调多少？”（每趟送多少？）→ 这就是决策变量。

Q2（分辨训练）：A 镇说“我们需要 100 吨水”。这句话，放进模型里是约束还是目标？为什么？

回答 A（硬约束）：如果把它写成 送达量A = 100，它就是一条硬约束——意味着“不救够 100 吨，模型就算失败”。

回答 B（软惩罚）：如果 100 吨只是“希望值”，就在目标函数里加一项 惩罚系数 × (100 − 送达量A)，让它变成目标函数的一部分。

回答 C（建模精髓）：同一句话可以放进不同的数学位置，表达不同的决策意图。

Q3（开放题，无标准答案，供课堂辩论用）：如果总物资不够所有人用，你是把物资平均分，还是优先满足某些城镇？这种“选择”在模型里怎么写？

回答 A（平均分配）：在模型中增加“比例公平约束”（送达量A / 需求A = 送达量B / 需求B）。

回答 B（优先级分配）：给不同城镇赋予不同的权重系数（wA, wB, wC），权重越高，目标函数越“偏爱”它。

回答 C（紧急程度分配）：把权重与“路况”“死伤率”挂钩，让数据来决定权重，而不是主观意愿。

回答 D（建模能力观）：这节课不判定哪种选择“对”，只考察学生能否把自己的选择转化为数学模型——这才是建模最核心的能力。

本模块的解决方法是“把问题拆成变量、约束、目标三要素”。教师可先给出 toy LP 让学生运行，再让他们把“需求 = 100 吨”分别改写为 x == 100 和 shortage = 100 - x 两种形式，观察可行域变化。重点讲解：决策变量要包含时间维度；约束是“不能突破的硬限制”；目标函数是“衡量好坏的标尺”。

2. 第一次完整建模：从要素到可运行模型

课堂过渡：我们已经知道变量、约束、目标分别是什么。现在把它们拼成一个可以运行的完整模型。这个模型不一定完美——它更像“第一稿”，接下来我们会看到它为什么可能崩溃，以及如何修复。

决策变量：

  • xw,t,h：第 t 小时从仓库 w 运往城镇 h 的物资吨数（连续 ≥ 0）
  • y：额外租用的直升机架次（整数 ≥ 0）
  • shortageh：城镇 h 的最终缺货量（连续 ≥ 0）

目标函数（最小化总损失）：

min Σ costw,h·xw,t,h + R·y + P·Σ shortageh + D·Σ t·xw,t,h

约束条件：

  1. 仓库库存：Σt,h xw,t,h ≤ 库存w
  2. 直升机运力：Σw,t,h xw,t,h ≤ (5 + y)·2·(72/3)
  3. 需求平衡：Σw,t xw,t,h + shortageh = 需求h
  4. 公平性：Σw,t xw,t,B ≥ 0.5·需求B
  5. 整数与非负：y ∈ Z≥0，所有变量 ≥ 0

注：这里的完整可运行代码已集中到第 8 节“L2 中阶模型”。本节重点理解如何把变量、约束、目标拼成第一个完整模型，以及它为什么可能在真实数据下崩溃。

启发问题：
  1. 如果缺货惩罚 P 从 1000 降到 10，模型还会租直升机吗？
  2. 如果把公平性约束从 50% 调到 90%，总成本会上升还是下降？为什么？
  3. 现实中，直升机往返时间不是精确的 3 小时，而是受天气影响。你会怎么修改模型？

核心引导提问

Q1（理解权重的作用）：在这个目标函数中，P（缺货惩罚系数）和 R（租金）之间存在一个隐含的“换算关系”。如果 P = 100 万且 R = 10 万，租一架直升机多运 2 吨物资能减少 2 吨缺货，节省 200 万罚款——你一定会租。如果 P = 5 万呢？模型还会租吗？

参考方向 1：不会。如果租一架直升机成本 10 万，而减少 2 吨缺货只节省 10 万（5 万 × 2 吨），刚好打平。

参考方向 2：如果 P < 5 万，租飞机反而亏钱，模型就会选择不租、承受缺货惩罚。

参考方向 3：这个计算揭示了一个本质：权重系数不是数学参数，它们是决策者的价值观在模型中的精确投影——你赋予缺货多大的惩罚值，决定了你在道德和经济之间的取舍。

Q2（解的存在性问题）：在写这个目标函数的时候，我们要先确认这个模型一定存在可行解。万一约束之间发现根本没有解，你准备调用哪一把手术刀去处理？

参考方向 1：检查模型的第一步永远是“可行性分析”。

参考方向 2：如果发现约束冲突（例如 B 镇的 50% 公平约束 + 直升机运力上限一起导致无解），先用手术刀 2（松弛变量）把“公平约束”降级为“惩罚项”。

参考方向 3：或者用手术刀 1 把某些等号改成小于等于。

参考方向 4：永远要设计一个“降级路径”，保证总有一个解存在（哪怕是最差解），而不是让模型直接无解崩溃。

Q3（全课总结开放题，作为课程的结语）：通过今天一整节课，我们处理了飓风救援的物资分配问题。如果只能用三句话向你的同事解释“优化建模到底是什么”，你会说哪三句话？

回答 A：“优化建模是用数学语言描述一个真实世界中的取舍问题。” —— 它始于一个现实的纠结（资源不够分），而不是始于一个抽象的公式。

回答 B：“你必须把所有‘常识’转化为可计算的约束或目标，模型没有良知。” —— 如果你不写“B 镇至少救 50%”，模型就会把 B 镇全部放弃；如果你不写“时间越晚价值越低”，模型就无视 72 小时窗口。

回答 C：“模型崩溃是给你送礼，提示你约束写得太死了。” —— 无可行解不是错误，而是提示你重新审视现实条件与理想目标之间的距离。松弛变量和预处理是你修复问题的标准工具。

教师参考：原文解决方法

本模块的解决方法是“完整 MILP 模型”：决策变量 xw,t,h（连续）、y（整数租赁架次）、shortageh（连续松弛）；目标函数最小化运输成本 + 租赁成本 + 缺货惩罚 + 延误惩罚；约束包括仓库库存、直升机总运力、需求平衡、公平性约束、整数与非负。教师可让学生先调参（改变 P、公平性比例、ROUND_TRIP），观察解的变化，体会“参数即价值观”。

3. 模型急诊室：无解时的三把手术刀

课堂过渡：上面的完整模型看起来很美，但现实中的数据经常会把它逼到“无可行解”。求解器报错时不要慌——那不是世界末日，而是模型在提醒你：约束写得太死了。下面三把手术刀就是标准修复流程。

当求解器返回 Infeasible 时，问题从不出在求解器身上，而是约束写得太死了。

崩溃类型根源手术刀
零资源把 0 值资源写进等式约束#1 删除相关变量，或把 = 改为 ≤
总供给 < 总需求强行要求满足 100% 需求#2 引入松弛变量 Shortage，在目标中加大惩罚
互斥约束冲突两条约束在数学上不相容#3 求解前预处理：自动调整阈值或报错

松弛变量的双重身份：同一个 shortageh 既出现在约束中（弥补缺口），又出现在目标函数中（被扣分）。它是连接“理想”与“现实”的数学桥梁。

启发问题：如果总运力为 0，你应该先试哪把手术刀？

import pulp

# --- Scenario: demand = 10, capacity = 5 ---

# Knife 0: hard constraint -> INFEASIBLE
prob_bad = pulp.LpProblem("Bad", pulp.LpMinimize)
x = pulp.LpVariable('x', lowBound=0)
prob_bad += x
prob_bad += x >= 10, "demand"
prob_bad += x <= 5,  "capacity"
prob_bad.solve(pulp.PULP_CBC_CMD(msg=0))
print("Hard-constraint model:", pulp.LpStatus[prob_bad.status])

# Knife 2: slack variable -> FEASIBLE
prob_good = pulp.LpProblem("Good", pulp.LpMinimize)
x2 = pulp.LpVariable('x2', lowBound=0)
s  = pulp.LpVariable('shortage', lowBound=0)
prob_good += 1000 * s                 # minimize shortage penalty
prob_good += x2 + s == 10, "demand"   # delivered + shortage = demand
prob_good += x2 <= 5, "capacity"      # capacity stays real
prob_good.solve(pulp.PULP_CBC_CMD(msg=0))
print("Slack-variable model:", pulp.LpStatus[prob_good.status])
print(f"Delivered: {pulp.value(x2):.2f}, Shortage: {pulp.value(s):.2f}")

核心引导提问

Q1（引出松弛变量）：假设我的目标是“让每个镇都获得全部需求”，但总物资远远不够。求解器报错“Infeasible”。如果不允许我修改目标，我还有别的办法吗？

参考方向 1：有。这是典型的“硬约束导致无解”情景。

参考方向 2：把“全部满足”改成“尽力满足但扣分”——引入松弛变量，把硬约束改成“+”，并在目标函数中加上巨大的惩罚系数。

参考方向 3：这样求解器发现“缺货”比“满足所有约束”更便宜时，就会选择一个缺货的最优解而不是直接崩溃。

参考方向 4：物理上，这就相当于允许救援行动“留遗憾”，但清楚知道每个遗憾的经济代价。

Q2（引出预处理）：如果 B 镇的公平约束是“至少 50 吨”，但所有仓库加起来只有 40 吨。除了报错，你还有什么办法？

参考方向 1：报错是最糟糕的用户体验。一个好的建模流程应该在求解器启动前先做数据完整性检查。

参考方向 2：如果 total_inventory < 50，可以自动将公平约束目标调整为 total_inventory，并打印警告信息。

参考方向 3：这就是手术刀 3 的思路——让模型在数据层面“自我修正”，而不是把错误留到求解器才暴露。

Q3（总结性提问，用于收尾模块）：我们今天讨论了三把“手术刀”——改等号、加松弛、删数据。假如你现在面对一个新问题，发现自己必须处理一个“总运力为 0”的情况，你会先试哪一把手术刀？

回答 A（先试手术刀 1）：如果总运力为 0，最优路径是先试手术刀 1——把所有涉及该运力的约束从 = 改为 ≤，因为 ≤ 0 会自动降为 0，模型会直接忽略这个资源，不会崩溃。

回答 B（组合使用）：如果还有别的刚性需求（比如“A 镇必须得到 100 吨”），则还需要手术刀 2——加入松弛变量，因为即使运力为 0，A 镇也可能通过其他路径获得部分物资。

回答 C（输入值不是错误）：总运力为 0 只是一个输入值，不是模型自身的错误——三把手术刀可以组合使用，顺序取决于约束的依赖关系。

教师参考：原文解决方法

本模块的解决方法是“三把手术刀”：#1 删除变量（或把 = 改为 ≤）处理零资源；#2 引入松弛变量 shortage 处理总供给不足；#3 求解前预处理发现并调和互斥约束。教师可用右侧代码演示：硬约束模型不可行，加入松弛变量后立即可行，并让学生理解 shortage 同时出现在约束和目标中的“双重身份”。

4. 六层透镜：把模型放到极端情境下检验

课堂过渡：模型已经有解了，但它是不是“好”的解？如果我们把某些条件推到极端，模型会不会给出荒谬结论？六层透镜就是一套系统性的“压力测试”清单，帮你在交卷前发现模型漏洞。

极端情境测试法：把某个条件推到极限值（0、无穷大、100 倍），观察模型是否会给出荒谬结论。如果会，说明遗漏了某个关键因素。

透镜极端问题逼出的数学产物救援案例
1. 稀缺性某资源变成 0，模型还能跑吗？用 ≤ 代替 =，或直接剔除变量3 号仓库被冲毁 → 删除其所有变量
2. 差异性A 镇人口是 B 镇 100 倍，模型会怎么做？权重系数 wh 或公平性约束给 B 镇加“至少满足 50% 需求”约束
3. 网络结构唯一道路断了，模型有第二条路吗？区分卡车/直升机运力约束B 镇只能靠直升机 → 单独写直升机约束
4. 时间维度1 小时必须送达 vs 现实 5 小时，价值还剩多少？衰减因子 e-λt 或阶梯惩罚晚 48 小时物资价值降至 30%
5. 离散性能派 0.5 架直升机吗？整数变量 y ∈ Z租用直升机架数必须是整数
6. 多目标冲突省钱和救人完全对立，选哪个？加权求和或词典序优化λ 是价值观，不是纯数学参数

课堂辩论题：总物资不够所有人用时，你是平均分配，还是优先某些城镇？这种“选择”在模型里怎么写？

· 平均分配 → 比例公平约束：送达A / 需求A = 送达B / 需求B

· 优先级分配 → 不同城镇权重 wA, wB, wC

· 按紧急程度 → 把权重与路况、伤亡率挂钩

启发问题：如果权重 wA = 100 × wB，模型会怎么做？你需要加什么约束来防止伦理上不可接受的解？

# --- Lens 2 demo: what happens with extreme weights? ---
import numpy as np

demand = {'A': 100000, 'B': 1000, 'C': 5000}
weights_extreme = {'A': 100, 'B': 1, 'C': 5}
total_supply = 30000  # not enough for everyone

# Greedy priority allocation
priority_order = sorted(demand.keys(), key=lambda h: -weights_extreme[h])
remaining = total_supply
allocation = {}
for h in priority_order:
    give = min(demand[h], remaining)
    allocation[h] = give
    remaining -= give

print("With extreme weights:")
for h in demand:
    pct = allocation[h] / demand[h] * 100
    print(f"  Town {h}: {allocation[h]:,} / {demand[h]:,} ({pct:.1f}%)")
print("\nLesson: extreme weights may zero out small towns.")
print("Add fairness constraints if that is unacceptable.")

核心引导提问

Q1（引出透镜 1）：假设 3 号仓库已经被洪水冲毁了（库存为 0），你的模型如果还写着“从 3 号仓库运出 = 库存”，会发生什么？

参考方向：求解器会报错“Infeasible（无可行解）”。问题不是被“0”搞崩溃的，而是被“等式”搞崩溃的。如果总需求大于其他仓库的总库存，模型无论如何也无法满足所有约束。正确做法是直接删除 3 号仓库的所有相关变量和约束。

Q2（引出透镜 2 与透镜 6 的交汇，开放辩论题）：A 镇 10 万人，B 镇 1000 人。如果模型按“救起人数最大化”来算，B 镇可能完全被放弃。你觉得这样的解是“最优”吗？如果不是，你需要在模型里加什么来防止这种情况？

回答 A（数学最优 ≠ 伦理最优）：数学上救 100 人永远优于救 1 人，但现实中我们不能因此放弃 B 镇。

回答 B（硬性公平约束）：直接写入 送达量B ≥ 50% × 需求B，强制模型不得完全放弃 B 镇。

回答 C（软性公平惩罚）：在目标函数中加上 + 100000 × 缺货量B，让放弃 B 镇的代价变得极其高昂。

回答 D（比例公平约束）：写入 送达量A / 需求A = 送达量B / 需求B，要求所有城镇获得相同的“拯救比例”。

回答 E（价值观表达）：这三个方案没有绝对的对错，取决于决策者的价值观——建模者的工作就是把决策者的价值观精准地翻译成数学语言。

Q3（引出透镜 3 和透镜 4 的结合）：B 镇只能通过直升机到达，且直升机往返需要 3 小时。如果救援窗口只有 72 小时，一架直升机最多飞几趟？这个数字是怎么算出来的，它应该放在模型里的哪个位置？

参考方向：一架直升机在 72 小时内最多飞 72 / 3 = 24 趟。乘以每趟 2 吨，总运力上限为 48 吨。这是一个物理铁律，应该放在约束条件里，写成 总直升机运量 ≤ 5 × 2 × 24。计算这个数字的过程，就是把“时间”这个抽象资源转化为“运力上限”这个具体约束。

Q4（引出透镜 5）：题目说“有 5 架直升机”，但你发现 5 架不够用，可以去租额外的飞机。那么“租几架”这个变量，是连续的还是整数的？它应该出现在约束里还是目标函数里，还是两个都要？

参考方向 1：租用架数必须是整数（y ∈ Z），因为不存在租半架直升机这种情况。

参考方向 2：在约束中：总运力上限 = 5 + y，它决定了物理可行域的大小。

参考方向 3：在目标函数中：+ 租金 × y，它决定了突破物理限制要付出的经济代价。

参考方向 4：整数规划的核心特征：决策变量本身既是“物理框架”的边界制造者，也是“经济账单”上的成本项。

教师参考：原文解决方法

本模块的解决方法是“六层透镜 + 极端情境测试”。原文从稀缺性、差异性、网络结构、时间维度、离散性、多目标冲突六个角度，把模糊因素转化为具体数学产物：稀缺性 → 删除变量或把 = 改为 ≤；差异性 → 权重或公平约束；网络结构 → 区分运输方式；时间维度 → 衰减/惩罚；离散性 → 整数变量；多目标冲突 → 加权求和或词典序优化。教师可让学生对每个透镜举一个“如果推到极端会怎样”的例子。

核心引导提问

Q1（检验分层理解）：物资（水和食物）和直升机，它们都是“资源”。为什么你建议把物资放进约束里，而直升机作为整数变量处理？

参考方向 1：物资是存量。它的总量是固定的，用完就没有了，无法在模型运行过程中“造”出更多来。所以它只能是边界，写在约束的右边（≤ 库存）。

参考方向 2：直升机是运力。如果数量可变（可租用），它就变成了一个决策变量——我们要决定“租多少”，这个决定既改变了物理上限（约束），又增加了成本（目标函数）。

参考方向 3：这就是为什么直升机必须同时出现在约束和目标函数两个地方。

Q2（引出时间作为惩罚）：为什么我不把“72 小时”写成“所有物资必须在 72 小时内送达”这样一条硬约束？

参考方向 1：你可以这样做：送达时间 ≤ 72 就是一条硬约束，模型会强制要求所有物资在 72 小时内到达。

参考方向 2：但现实是：某些偏远城镇可能确实需要 73 小时。强行写入硬约束会导致模型“无可行解”，直接崩溃。

参考方向 3：更灵活的做法是把时间处理成惩罚项：总损失 += 延误小时数 × 单位时间人命价值。这样模型会主动把物资优先发给远距离城镇，而不是为了满足硬性截止时间而崩溃。

Q3（综合应用的开放题，适合小组辩论）：B 镇的道路被毁，唯一的通道是直升机，而你的直升机既要运货又要侦察。你打算在模型中如何区分“侦察飞行”和“运输飞行”这两种不同的运力消耗？

回答 A（资源竞争意识）：如果每架直升机每天只有一定飞行小时数，侦察任务和运输任务会同时消耗这个总飞行时间，存在直接的资源竞争。

回答 B（精细化方案）：把直升机运力进一步细分为“侦察小时数”和“运输小时数”，分别写入不同的约束，但共享同一个“总飞行时间”上限。

回答 C（简化方案）：统一视为“总可用架次”，将两种任务综合在一起处理，不区分用途。

回答 D（建模选择）：没有绝对的对错——但建模者必须意识到这种“资源内部竞争”的存在，并明确其在数学模型中的表达方式。

教师参考：原文解决方法

本模块的解决方法是“三层资源金字塔”：顶层实物存量（库存、资金）写成 ≤ 约束；中层运力流量（自有/租用直升机）如果是固定的写约束，如果是可决策的同时出现在约束和目标里；底层时空衰减（延误、价值下降）写成目标函数惩罚。教师可让学生现场对 5～6 个因素分类，并解释“为什么”放在那里。

6. 延伸 1：区分卡车与直升机两种运输方式

课堂过渡：基础模型假设只有一种运输方式。现实中道路可能部分损毁：卡车便宜但到不了某些镇，直升机贵但全覆盖。下面把单一变量拆成 x_truck 和 x_heli，看看网络结构如何改变模型。

现实中，不同运输方式的运力约束是分开的。假设 A、C 两镇道路畅通可用卡车，B 镇道路被毁只能用直升机。

新增变量：

  • x_heli[w,t,h]：直升机从仓库 w 到城镇 h 的运量（h ∈ {A, B, C}）

7. 延伸 2：把时间惩罚改为指数衰减

课堂过渡：基础模型用线性惩罚 D·t·x 衡量延误。但灾后救援的特点是“前几个小时价值最高”，价值随时间指数衰减。下面把线性惩罚换成指数价值函数，观察解的时间分布如何变化。

线性惩罚 D·t·x 假设每小时延误的代价相同。现实中，灾后前几个小时救人价值最高，之后价值迅速衰减。

价值函数：

第 t 小时送达 1 吨物资的价值 = V0 · e-λt

目标变为 最大化总价值 − 总成本，等价于最小化 总成本 − 总价值。

注意：含 e-λt 的目标是非线性的，可用 scipy 求解连续变量版本。若需保留整数变量（租直升机架次），需要使用 MINLP 求解器。

启发问题：λ 越大，模型越倾向于把物资集中在哪些小时送达？如果把 λ 设为 0，模型行为会变成什么？

注：含指数衰减价值的完整可运行代码见第 8 节“L3 高阶模型”。

核心引导提问

Q1：指数衰减价值函数与线性延误惩罚在模型行为上有什么不同？

参考方向：线性惩罚假设每小时延误代价相同，解可能把物资均匀分散在时间上；指数衰减则强调“灾后前几个小时价值最高”，λ 越大，模型越倾向于把物资集中在前面几小时送达。为防止所有物资挤在第 0 小时，需要额外加上每小时运力上限。

Q2（开放）：如果 λ = 0，模型行为会变成什么样？请给出多种合理推断。

回答 A：λ = 0 意味着送达时间不影响价值，目标退化为最小化运输成本，物资会从最便宜的仓库出发。

回答 B：如果同时 D = 0，模型完全不在乎延误，所有需求可能集中到成本最低的路线，即使很晚送达。

回答 C：λ = 0 时指数项恒为 1，目标函数中“价值”变成与 t 无关的常数，无法体现时间紧迫性。

回答 D：这说明 λ 不是纯数学参数，而是对“时间价值”的价值观设定，需要与领域专家共同确定。

教师参考：原文解决方法

本延伸的解决方法是“指数衰减时间价值”：把第 t 小时送达物资的价值写成 V0·e-λt，目标函数改为最大化总价值 − 总成本（等价于最小化 总成本 − 总价值）。由于目标含 e-λt，模型变为非线性，可用 scipy.optimize.minimize (SLSQP) 解连续变量版本；若保留整数变量则需 MINLP 求解器。为避免所有物资挤在第 0 小时，必须加入每小时运力上限约束。教师可让学生分别比较 λ = 0.05、0.15、0.5 时的平均送达时间。

L1 初阶模型：静态线性分配（LP）

设计思路

把问题简化成“从仓库到城镇的最小成本运输”。不考虑时间、不考虑租机、不允许缺货。适合第一次接触优化的学生：变量只有 x[w][h]，目标函数和约束都是线性的。

指标定义
  • w ∈ W：仓库集合，例如 W1、W2、W3。
  • h ∈ H：受灾城镇集合，例如 A、B、C。
  • xwh：从仓库 w 运往城镇 h 的物资吨数（连续非负决策变量）。
  • cwh：从仓库 w 到城镇 h 的单位运输成本（美元/吨）。
  • inventoryw：仓库 w 的初始库存（吨）。
  • demandh：城镇 h 的最低需求量（吨）。
目标方程

min Σw∈W,h∈H cwh · xwh

最小化总运输成本。

约束考量
  • 库存约束：每个仓库运出总量 ≤ 库存。
  • 需求约束：每个城镇收到总量 = 需求量（硬约束，不允许短缺）。
  • 非负约束：运量不能为负。
import pulp

# ==================== 1. 数据准备 ====================
# WAREHOUSES: 仓库集合 w
WAREHOUSES = ['W1', 'W2', 'W3']
# TOWNS: 受灾城镇集合 h
TOWNS = ['A', 'B', 'C']

# inventory[w]: 仓库 w 的初始库存（吨）
inventory = {'W1': 12, 'W2': 15, 'W3': 10}
# demand[h]: 城镇 h 的最低需求量（吨）
demand = {'A': 10, 'B': 12, 'C': 8}
# cost[w][h]: 从仓库 w 到城镇 h 的单位运输成本（美元/吨）
cost = {
    'W1': {'A': 3, 'B': 5, 'C': 7},
    'W2': {'A': 6, 'B': 2, 'C': 4},
    'W3': {'A': 8, 'B': 4, 'C': 3},
}

# ==================== 2. 创建模型 ====================
# 定义一个最小化问题，命名为 Rescue_Level1
prob = pulp.LpProblem('Rescue_Level1', pulp.LpMinimize)

# 决策变量 x[w][h]: 从仓库 w 运往城镇 h 的物资吨数
# lowBound=0 表示运量不能为负（非负约束）
x = pulp.LpVariable.dicts('x', (WAREHOUSES, TOWNS), lowBound=0)

# ==================== 3. 目标函数 ====================
# 最小化总运输成本 = sum(单位成本 * 运量) 对所有 (w, h) 组合
prob += pulp.lpSum(cost[w][h] * x[w][h]
                   for w in WAREHOUSES for h in TOWNS)

# ==================== 4. 约束条件 ====================
# 约束 1：每个仓库运出量不超过其库存
# 对每一个仓库 w：sum(x[w][h] for all h) <= inventory[w]
for w in WAREHOUSES:
    prob += pulp.lpSum(x[w][h] for h in TOWNS) <= inventory[w], f'inventory_{w}'

# 约束 2：每个城镇必须恰好满足需求（L1 不允许短缺）
# 对每一个城镇 h：sum(x[w][h] for all w) == demand[h]
for h in TOWNS:
    prob += pulp.lpSum(x[w][h] for w in WAREHOUSES) == demand[h], f'demand_{h}'

# ==================== 5. 求解并输出结果 ====================
# 使用 CBC 求解器，msg=0 表示不输出求解器内部日志
prob.solve(pulp.PULP_CBC_CMD(msg=0))

# prob.status 是数值状态码，LpStatus 把它转成可读字符串（Optimal / Infeasible 等）
print('Status:', pulp.LpStatus[prob.status])
# prob.objective 是目标函数表达式，用 pulp.value 取最优值
print('Total cost:', pulp.value(prob.objective))

# 遍历所有 (w, h) 组合，打印运量大于 0.001 吨的方案
for w in WAREHOUSES:
    for h in TOWNS:
        val = pulp.value(x[w][h])
        if val > 0.001:
            print(f'{w} -> {h}: {val:.2f} tons')

L2 中阶模型：松弛变量 + 整数租机（MILP）

设计思路

在 L1 基础上承认现实：总运力可能不够，需求可能无法 100% 满足。引入短缺变量 shortage[h] 作为“松动的口子”，并允许以整数数量租用额外直升机。目标函数把短缺和租机都变成“钱”，让模型自己权衡。

指标定义
  • w ∈ W：仓库集合；h ∈ H：受灾城镇集合。
  • xwh：从仓库 w 运往城镇 h 的物资吨数（连续非负）。
  • shortageh：城镇 h 最终仍未满足的需求量（连续非负松弛变量）。
  • rental：额外租用的直升机架次（整数非负决策变量）。
  • cwh：单位运输成本；R：每架租机总成本；P：每吨缺货惩罚。
  • OWN_HELI：自有直升机数量；HELI_LOAD：每架次载重（吨）。
目标方程

min Σw∈W,h∈H cwh·xwh + R·rental + P·Σh∈H shortageh

运输成本 + 租机成本 + 缺货惩罚。P 越大，模型越不愿意短缺。

约束考量
  • 库存约束：同 L1。
  • 需求约束变软：deliveredh + shortageh = demandh。
  • 运力约束：总运量 ≤ (自有直升机 + 租机) × 单架载重。
  • 公平性约束：每个城镇至少获得 50% 需求，避免模型放弃小城。
  • 整数约束：rental 为整数。
import pulp

# ==================== 1. 数据准备 ====================
WAREHOUSES = ['W1', 'W2', 'W3']   # 仓库集合 w
TOWNS = ['A', 'B', 'C']           # 城镇集合 h

inventory = {'W1': 12, 'W2': 15, 'W3': 10}  # inventory[w]: 仓库 w 库存（吨）
demand = {'A': 10, 'B': 12, 'C': 8}         # demand[h]: 城镇 h 需求量（吨）
# cost[w][h]: 从仓库 w 到城镇 h 的单位运输成本（美元/吨）
cost = {
    'W1': {'A': 3, 'B': 5, 'C': 7},
    'W2': {'A': 6, 'B': 2, 'C': 4},
    'W3': {'A': 8, 'B': 4, 'C': 3},
}

OWN_HELI = 4          # 自有直升机数量
HELI_LOAD = 2         # 每架直升机单次可运吨数
RENTAL_COST = 50      # 租用一架直升机的总成本（美元）
SHORTAGE_PENALTY = 100  # 每吨未满足需求的惩罚成本（美元/吨）

# ==================== 2. 创建模型 ====================
prob = pulp.LpProblem('Rescue_Level2', pulp.LpMinimize)

# x[w][h]: 从仓库 w 运往城镇 h 的物资吨数（连续非负）
x = pulp.LpVariable.dicts('x', (WAREHOUSES, TOWNS), lowBound=0)
# shortage[h]: 城镇 h 未被满足的需求量（连续非负松弛变量）
shortage = pulp.LpVariable.dicts('shortage', TOWNS, lowBound=0)
# rental: 额外租用的直升机架次（整数非负决策变量）
rental = pulp.LpVariable('rental', lowBound=0, cat='Integer')

# ==================== 3. 目标函数 ====================
# 总成本 = 运输成本 + 租机成本 + 缺货惩罚
# 模型会在这三者之间自动权衡：当缺货惩罚很高时，宁愿多租直升机
prob += (
    pulp.lpSum(cost[w][h] * x[w][h] for w in WAREHOUSES for h in TOWNS)
    + RENTAL_COST * rental
    + SHORTAGE_PENALTY * pulp.lpSum(shortage[h] for h in TOWNS)
)

# ==================== 4. 约束条件 ====================
# 约束 1：每个仓库运出总量不超过其库存
for w in WAREHOUSES:
    prob += pulp.lpSum(x[w][h] for h in TOWNS) <= inventory[w]

# 约束 2：需求 = 实际送达量 + 短缺量
# 允许 shortage[h] > 0，意味着模型可以“接受”部分需求未被满足
for h in TOWNS:
    prob += pulp.lpSum(x[w][h] for w in WAREHOUSES) + shortage[h] == demand[h]

# 约束 3：总运输量不能超过（自有 + 租用）直升机的总运力
# 注意：rental 是变量，因此总容量 (OWN_HELI + rental) * HELI_LOAD 随决策变化
total_capacity = (OWN_HELI + rental) * HELI_LOAD
prob += pulp.lpSum(x[w][h] for w in WAREHOUSES for h in TOWNS) <= total_capacity

# 约束 4：公平性约束——每个城镇至少获得 50% 的需求
# 避免模型为了省钱而放弃小城市
for h in TOWNS:
    prob += pulp.lpSum(x[w][h] for w in WAREHOUSES) >= 0.5 * demand[h]

# ==================== 5. 求解并输出结果 ====================
prob.solve(pulp.PULP_CBC_CMD(msg=0))

print('Status:', pulp.LpStatus[prob.status])
print('Total cost:', pulp.value(prob.objective))
print('Rental helicopters:', pulp.value(rental))

for h in TOWNS:
    # 计算城镇 h 实际收到的总物资
    delivered = pulp.value(pulp.lpSum(x[w][h] for w in WAREHOUSES))
    print(f'Town {h}: delivered {delivered:.2f}, shortage {pulp.value(shortage[h]):.2f}')

L3 高阶模型：时间轴 + 多模式 + 指数价值（NLP）

设计思路

灾后救援的物资价值随时间衰减：第 1 小时送到的水和第 10 小时送到的水价值不同。同时道路可能受损，卡车便宜但到不了某些城镇，直升机贵但全覆盖。L3 把这两个现实因素同时纳入：12 小时时间轴、两种运输方式、指数衰减价值函数。

指标定义
  • w ∈ W：仓库；h ∈ H：城镇；t ∈ T：小时（0 到 11）。
  • m ∈ M：运输方式，m = 0 为卡车，m = 1 为直升机。
  • xw,t,h,m：第 t 小时从仓库 w 用方式 m 运往城镇 h 的物资吨数（连续非负）。
  • cw,h,m：方式 m 从 w 到 h 的单位运输成本；999 表示卡车不可达。
  • V0：第 0 小时送达每吨物资的价值；λ：价值衰减率。
  • TRUCK_CAP / HELI_CAP：卡车/直升机每小时的总运力上限（吨/小时）。
目标方程

min Σw,t,h,m cw,h,m·xw,t,h,m − V0·Σw,t,h,m xw,t,h,m·e−λt

最小化“成本 − 时间折现价值”。λ 越大，模型越倾向于早送达。

约束考量
  • 库存约束：每个仓库在所有时间、所有方式运出总量 ≤ 库存。
  • 需求约束：每个城镇累计收到量 = 需求量。
  • 每小时运力约束：卡车和直升机各有独立的每小时运力上限。
  • 可达性约束：卡车无法到达的线路用极大成本 999 模拟。
  • 公平性约束：每个城镇至少获得 50% 需求。
注意：由于目标函数含 e−λt，模型变为非线性。这里用 scipy.optimize.minimize (trust-constr) 解连续变量版本；若要求整数运量，需要 MINLP 求解器如 Couenne、Bonmin 或 Pyomo + Baron。 
import warnings
# scipy 在求解线性目标时可能打印 "delta_grad == 0.0" 的提示，这里忽略它
warnings.filterwarnings('ignore', message='delta_grad == 0.0')
import numpy as np
from scipy.optimize import minimize

# ==================== 1. 数据准备 ====================
WAREHOUSES = ['W1', 'W2', 'W3']   # 仓库集合 w
TOWNS = ['A', 'B', 'C']           # 城镇集合 h
HOURS = list(range(12))           # 时间轴 t = 0, 1, ..., 11

inventory = {'W1': 12, 'W2': 15, 'W3': 10}  # inventory[w]: 仓库 w 库存
demand = {'A': 10, 'B': 12, 'C': 8}         # demand[h]: 城镇 h 需求

# TRUCK_COST[w][h]: 卡车从 w 到 h 的单位成本；999 表示该线路因道路损坏不可达
TRUCK_COST = {
    'W1': {'A': 1, 'B': 2, 'C': 999},
    'W2': {'A': 2, 'B': 1, 'C': 3},
    'W3': {'A': 999, 'B': 2, 'C': 1},
}
# HELI_COST[w][h]: 直升机从 w 到 h 的单位成本（直升机可以到达所有城镇）
HELI_COST = {
    'W1': {'A': 3, 'B': 5, 'C': 7},
    'W2': {'A': 6, 'B': 2, 'C': 4},
    'W3': {'A': 8, 'B': 4, 'C': 3},
}

TRUCK_CAP = 5          # 每小时所有卡车的总运力上限（吨/小时）
HELI_CAP = 8           # 每小时所有直升机的总运力上限（吨/小时）
VALUE_PER_TON = 50     # 第 0 小时送达 1 吨物资的价值（美元）
LAMBDA = 0.15          # 价值衰减率：越大表示越早送达越重要

# ==================== 2. 变量编码 ====================
# 决策变量 x_{w,t,h,m} 是四维的，但 scipy 只接受一维向量。
# 因此用 idx() 把 (w, t, h, mode) 映射到一维向量的位置。
# mode = 0: 卡车；mode = 1: 直升机

def idx(w, t, h, mode):
    """把四维索引 (仓库, 小时, 城镇, 方式) 映射到一维向量位置。"""
    return ((WAREHOUSES.index(w) * len(HOURS) + t) * len(TOWNS) + TOWNS.index(h)) * 2 + mode

# 总变量数 = 仓库数 × 小时数 × 城镇数 × 方式数
n_vars = len(WAREHOUSES) * len(HOURS) * len(TOWNS) * 2

# ==================== 3. 目标函数 ====================
# 目标 = 总运输成本 - 总时间折现价值
# 其中价值项含 e^{-λt}，使越早送达的物资价值越高
def objective(x):
    # 运输成本：根据方式选择对应的成本矩阵
    transport = sum(
        (TRUCK_COST[w][h] if m == 0 else HELI_COST[w][h]) * x[idx(w, t, h, m)]
        for w in WAREHOUSES for t in HOURS for h in TOWNS for m in [0, 1]
    )
    # 时间折现价值：第 t 小时送达的物资价值为 V0 * e^{-λt}
    value = sum(
        x[idx(w, t, h, m)] * VALUE_PER_TON * np.exp(-LAMBDA * t)
        for w in WAREHOUSES for t in HOURS for h in TOWNS for m in [0, 1]
    )
    return transport - value

# ==================== 4. 变量边界与约束 ====================
# 所有决策变量非负：0 <= x < +∞
bounds = [(0, None) for _ in range(n_vars)]
constraints = []

# 约束 1：每个仓库在所有时间、所有方式运出的总量不超过库存
for w in WAREHOUSES:
    constraints.append({
        'type': 'ineq',
        'fun': lambda x, w=w: inventory[w] - sum(
            x[idx(w, t, h, m)] for t in HOURS for h in TOWNS for m in [0, 1]
        )
    })

# 约束 2：每个城镇在所有时间、所有方式累计收到的总量等于需求
for h in TOWNS:
    constraints.append({
        'type': 'eq',
        'fun': lambda x, h=h: sum(
            x[idx(w, t, h, m)] for w in WAREHOUSES for t in HOURS for m in [0, 1]
        ) - demand[h]
    })

# 约束 3：每小时卡车的总运量不超过卡车运力上限
for t in HOURS:
    constraints.append({
        'type': 'ineq',
        'fun': lambda x, t=t: TRUCK_CAP - sum(
            x[idx(w, t, h, 0)] for w in WAREHOUSES for h in TOWNS
        )
    })

# 约束 4：每小时直升机的总运量不超过直升机运力上限
for t in HOURS:
    constraints.append({
        'type': 'ineq',
        'fun': lambda x, t=t: HELI_CAP - sum(
            x[idx(w, t, h, 1)] for w in WAREHOUSES for h in TOWNS
        )
    })

# 约束 5：公平性约束——每个城镇累计获得量不低于 50% 需求
for h in TOWNS:
    constraints.append({
        'type': 'ineq',
        'fun': lambda x, h=h: sum(
            x[idx(w, t, h, m)] for w in WAREHOUSES for t in HOURS for m in [0, 1]
        ) - 0.5 * demand[h]
    })

# ==================== 5. 求解并输出结果 ====================
# 初始猜测：全零向量
x0 = np.zeros(n_vars)
# 使用 trust-constr 方法求解带约束的非线性优化问题
res = minimize(objective, x0, method='trust-constr', bounds=bounds, constraints=constraints,
               options={'maxiter': 1000})

print('Success:', res.success)
print('Objective (cost - value):', f'${res.fun:.2f}')

# 把一维解向量还原为四维数组 (w, t, h, mode)
X = res.x.reshape(len(WAREHOUSES), len(HOURS), len(TOWNS), 2)

# 检查每个城镇的总送达量
for h in TOWNS:
    delivered = X[:, :, TOWNS.index(h), :].sum()
    print(f'Town {h}: delivered {delivered:.2f} / {demand[h]}')

# 展示每小时两种运输方式的总运量
print('\nHourly truck shipment:', X[:, :, :, 0].sum(axis=(0, 2)).round(2))
print('Hourly heli shipment:', X[:, :, :, 1].sum(axis=(0, 2)).round(2))

核心引导提问

Q1：从 L1 到 L2，再到 L3，每一次“升级”到底多了什么现实因素？

回答 A（L1 → L2）：从“理想世界”进入“资源不够的真实世界”：允许短缺、可以租机、加入公平性。

回答 B（L2 → L3）：从“单周期快照”进入“动态时间轴”：考虑何时送达、区分运输方式、用指数函数刻画时间价值。

回答 C：每一次升级都不是凭空加复杂度，而是为了回答一个更真实的决策问题。

Q2（开放）：如果让你继续升级到 L4，你会加什么？

回答 A：加入随机性，比如需求、道路可达性、天气都是随机的，用随机规划或鲁棒优化。

回答 B：加入多目标优化：同时最小化成本、最大化公平性、最小化最大延误，画 Pareto 前沿。

回答 C：把问题变成多阶段决策：每隔几小时根据最新灾情信息重新优化（滚动时域）。

回答 D：引入真实 GIS 路网，用 Dijkstra / Floyd 计算每个仓库到城镇的最短通行时间。

9. 情境分析与敏感性分析：模型不是单点答案

课堂上的模型通常只跑一组“基线数据”，但真实决策必须在不确定中做。 情境分析（Scenario Analysis）回答的是：“如果现实结构变了，方案还成立吗？” 敏感性分析（Sensitivity Analysis）回答的是：“如果某个参数估计偏了，结果会怎么偏？” 二者合起来，才能判断一个方案是不是“鲁棒”的。

情境分析 = 改变结构

仓库被冲毁、需求翻倍、直升机故障、道路全断……这些都是“输入结构”的变化，不是单纯改数字。

敏感性分析 = 改变参数

缺货惩罚 P、公平比例、衰减率 λ、运力上限……这些都是“参数”的变化，看最优解如何漂移。

常用情境设计
情境结构变化观察重点
基线使用原始数据成本、租机数、缺货量
W3 被毁inventory['W3'] = 0哪些城镇被迫短缺？租金涨多少？
B 镇需求翻倍demand['B'] = 24公平性约束是否 still 可行？是否必须多租直升机？
直升机故障OWN_HELI 从 4 降为 3短缺是否从 B 镇转移到 A、C？

课堂用法：让学生先预测“哪个情境会让总成本飙升”，再运行代码验证。预测与结果的差距，往往是建模直觉最好的训练。

import pulp

# ==================== L2 情境分析 ====================
def solve_l2(inventory, demand, own_heli):
    """给定库存、需求、自有直升机数，返回（总成本，租机数，总缺货量）。"""
    WAREHOUSES = list(inventory.keys())
    TOWNS = list(demand.keys())
    cost = {
        'W1': {'A': 3, 'B': 5, 'C': 7},
        'W2': {'A': 6, 'B': 2, 'C': 4},
        'W3': {'A': 8, 'B': 4, 'C': 3},
    }
    HELI_LOAD = 2
    RENTAL_COST = 50
    SHORTAGE_PENALTY = 100

    prob = pulp.LpProblem('Rescue_L2_Scenario', pulp.LpMinimize)
    x = pulp.LpVariable.dicts('x', (WAREHOUSES, TOWNS), lowBound=0)
    shortage = pulp.LpVariable.dicts('shortage', TOWNS, lowBound=0)
    rental = pulp.LpVariable('rental', lowBound=0, cat='Integer')

    prob += (
        pulp.lpSum(cost[w][h] * x[w][h] for w in WAREHOUSES for h in TOWNS)
        + RENTAL_COST * rental
        + SHORTAGE_PENALTY * pulp.lpSum(shortage[h] for h in TOWNS)
    )

    for w in WAREHOUSES:
        prob += pulp.lpSum(x[w][h] for h in TOWNS) <= inventory[w]

    for h in TOWNS:
        prob += pulp.lpSum(x[w][h] for w in WAREHOUSES) + shortage[h] == demand[h]
        prob += pulp.lpSum(x[w][h] for w in WAREHOUSES) >= 0.5 * demand[h]

    prob += pulp.lpSum(x[w][h] for w in WAREHOUSES for h in TOWNS) <= (own_heli + rental) * HELI_LOAD

    prob.solve(pulp.PULP_CBC_CMD(msg=0))

    status = pulp.LpStatus[prob.status]
    if status != 'Optimal':
        return status, None, None, None

    total_shortage = sum(pulp.value(shortage[h]) for h in TOWNS)
    return status, pulp.value(prob.objective), pulp.value(rental), total_shortage

参数含义预期效果

import pulp

# ==================== L2 敏感性分析 ====================
def l2_param_sweep(penalty=None, fair_ratio=None):
    """只改一个参数，其它保持默认。"""
    inventory = {'W1': 12, 'W2': 15, 'W3': 10}
    demand = {'A': 10, 'B': 12, 'C': 8}
    WAREHOUSES = list(inventory.keys())
    TOWNS = list(demand.keys())
    cost = {
        'W1': {'A': 3, 'B': 5, 'C': 7},
        'W2': {'A': 6, 'B': 2, 'C': 4},
        'W3': {'A': 8, 'B': 4, 'C': 3},
    }
    OWN_HELI, HELI_LOAD = 4, 2
    RENTAL_COST = 50
    P = penalty if penalty is not None else 100
    alpha = fair_ratio if fair_ratio is not None else 0.5

    prob = pulp.LpProblem('L2_Sweep', pulp.LpMinimize)
    x = pulp.LpVariable.dicts('x', (WAREHOUSES, TOWNS), lowBound=0)
    shortage = pulp.LpVariable.dicts('shortage', TOWNS, lowBound=0)
    rental = pulp.LpVariable('rental', lowBound=0, cat='Integer')

    prob += (
        pulp.lpSum(cost[w][h] * x[w][h] for w in WAREHOUSES for h in TOWNS)
        + RENTAL_COST * rental
        + P * pulp.lpSum(shortage[h] for h in TOWNS)
    )

    for w in WAREHOUSES:
        prob += pulp.lpSum(x[w][h] for h in TOWNS) <= inventory[w]
    for h in TOWNS:
        prob += pulp.lpSum(x[w][h] for w in WAREHOUSES) + shortage[h] == demand[h]
        prob += pulp.lpSum(x[w][h] for w in WAREHOUSES) >= alpha * demand[h]
    prob += pulp.lpSum(x[w][h] for w in WAREHOUSES for h in TOWNS) <= (OWN_HELI + rental) * HELI_LOAD

    prob.solve(pulp.PULP_CBC_CMD(msg=0))
    status = pulp.LpStatus[prob.status]
    if status != 'Optimal':
        return status, None, None, None
    return status, pulp.value(prob.objective), pulp.value(rental), sum(pulp.value(shortage[h]) for h in TOWNS)

L3 的 λ 敏感性

在 L3 中，λ 控制“早送”有多重要。λ = 0 时模型只在乎成本；λ 很大时，模型会尽可能把物资压到前几个小时，即使直升机更贵。

观察指标：平均送达小时、卡车/直升机总运量、目标函数值。

启发问题：如果 λ 很大，为什么解反而可能总成本更高？这对应现实中的什么取舍？

import numpy as np
from scipy.optimize import linprog

# ==================== L3：λ 敏感性分析 ====================
# L3 的目标函数其实是线性的：e^{-λt} 对给定 λ 是常数系数。
# 因此可以用 scipy.linprog (HiGHS) 快速求解，而不用非线性迭代。
WAREHOUSES = ['W1', 'W2', 'W3']
TOWNS = ['A', 'B', 'C']
HOURS = list(range(12))

inventory = {'W1': 12, 'W2': 15, 'W3': 10}
demand = {'A': 10, 'B': 12, 'C': 8}

TRUCK_COST = {
    'W1': {'A': 1, 'B': 2, 'C': 999},
    'W2': {'A': 2, 'B': 1, 'C': 3},
    'W3': {'A': 999, 'B': 2, 'C': 1},
}
HELI_COST = {
    'W1': {'A': 3, 'B': 5, 'C': 7},
    'W2': {'A': 6, 'B': 2, 'C': 4},
    'W3': {'A': 8, 'B': 4, 'C': 3},
}

TRUCK_CAP = 5
HELI_CAP = 8
VALUE_PER_TON = 50


def idx(w, t, h, mode):
    """把 (仓库, 小时, 城镇, 方式) 映射到一维变量下标。"""
    return ((WAREHOUSES.index(w) * len(HOURS) + t) * len(TOWNS) + TOWNS.index(h)) * 2 + mode


n_vars = len(WAREHOUSES) * len(HOURS) * len(TOWNS) * 2


def solve_l3(lam):
    # 目标函数系数：运输成本 - 时间折现价值
    c = np.zeros(n_vars)
    for w in WAREHOUSES:
        for t in HOURS:
            for h in TOWNS:
                for m in [0, 1]:
                    i = idx(w, t, h, m)
                    c[i] = (TRUCK_COST[w][h] if m == 0 else HELI_COST[w][h]) - VALUE_PER_TON * np.exp(-lam * t)

    A_ub, b_ub = [], []
    # 库存约束：每个仓库运出总量 <= 库存
    for w in WAREHOUSES:
        row = np.zeros(n_vars)
        for t in HOURS:
            for h in TOWNS:
                for m in [0, 1]:
                    row[idx(w, t, h, m)] = 1
        A_ub.append(row)
        b_ub.append(inventory[w])

    # 每小时运力约束
    for t in HOURS:
        row_truck = np.zeros(n_vars)
        row_heli = np.zeros(n_vars)
        for w in WAREHOUSES:
            for h in TOWNS:
                row_truck[idx(w, t, h, 0)] = 1
                row_heli[idx(w, t, h, 1)] = 1
        A_ub.append(row_truck); b_ub.append(TRUCK_CAP)
        A_ub.append(row_heli);  b_ub.append(HELI_CAP)

    # 公平性约束：每个城镇获得量 >= 0.5 * 需求，写成 -sum <= -0.5*demand
    for h in TOWNS:
        row = np.zeros(n_vars)
        for w in WAREHOUSES:
            for t in HOURS:
                for m in [0, 1]:
                    row[idx(w, t, h, m)] = -1
        A_ub.append(row)
        b_ub.append(-0.5 * demand[h])

    # 需求约束：每个城镇累计收到量 == 需求量
    A_eq, b_eq = [], []
    for h in TOWNS:
        row = np.zeros(n_vars)
        for w in WAREHOUSES:
            for t in HOURS:
                for m in [0, 1]:
                    row[idx(w, t, h, m)] = 1
        A_eq.append(row)
        b_eq.append(demand[h])

    res = linprog(c, A_ub=np.array(A_ub), b_ub=np.array(b_ub),
                  A_eq=np.array(A_eq), b_eq=np.array(b_eq),
                  bounds=[(0, None)] * n_vars, method='highs')
    return res


print(f'{"lambda":>7} {"成功":>6} {"平均小时":>10} {"卡车总量":>10} {"直升机总量":>12} {"目标值":>10}')
for lam in [0.0, 0.05, 0.15, 0.5]:
    res = solve_l3(lam)
    if res.success:
        X = res.x.reshape(len(WAREHOUSES), len(HOURS), len(TOWNS), 2)
        total = X.sum()
        avg_hour = sum(t * X[:, t, :, :].sum() for t in HOURS) / total
        truck_total = X[:, :, :, 0].sum()
        heli_total = X[:, :, :, 1].sum()
        print(f'{lam:>7.2f} {"Yes":>6} {avg_hour:>10.2f} {truck_total:>10.2f} {heli_total:>12.2f} {res.fun:>10.2f}')
    else:
        print(f'{lam:>7.2f} {"No":>6} {"-":>10} {"-":>10} {"-":>12} {"-":>10}')

核心引导提问

Q1：情境分析和敏感性分析有什么不同？为什么两者都要做？

回答 A：情境分析改变的是“故事结构”，比如仓库被毁；敏感性分析改变的是“数字大小”，比如惩罚系数。前者看方案是否还成立，后者看最优解往哪边偏。

回答 B：只做敏感性分析，可能漏掉黑天鹅事件；只做情境分析，可能不知道参数估计误差的影响。两者互补。

Q2（开放）：如果 P 从 100 提到 10000，租机数一定会增加吗？有没有可能不变？

回答 A：不一定。如果现有运力已经足以满足所有需求，再提高 P 也不会多租直升机。

回答 B：这说明“提高惩罚”只有在存在短缺空间时才有效果。模型中的政策干预必须落在真正的瓶颈上。

Q3：在 L3 中，λ 越大平均送达时间越小，但成本可能越高。这个 trade-off 怎么向决策者解释？

回答 A：可以画一张“平均送达时间 vs 总成本”的 Pareto 曲线，让决策者选择自己能接受的点。

回答 B：λ 本质上是在问：“你愿意多花多少钱，把物资早送一小时？”这个数字应该由领域专家或决策者给出，而不是建模者拍脑袋。
